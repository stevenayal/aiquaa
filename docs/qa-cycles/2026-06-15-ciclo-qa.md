## 🔐 Seguridad — Hallazgos (Supabase Advisors)

### 🔴 CRÍTICO — `change_user_role` accesible por cualquier usuario autenticado

```
Función: public.change_user_role(target_user_id uuid, new_role text)
Endpoint: POST /rest/v1/rpc/change_user_role
Acceso: authenticated (SECURITY DEFINER)
```

Cualquier usuario registrado puede llamar esta función y escalar el rol de cualquier otro usuario (o el suyo propio) a admin. **Vector de escalada de privilegios.**

**Acción inmediata:**
```sql
REVOKE EXECUTE ON FUNCTION public.change_user_role(uuid, text) FROM authenticated;
-- Solo debe ejecutarse desde service_role.
```

### 🔴 CRÍTICO — RLS habilitado sin políticas en 11 tablas

Tablas afectadas: `challenge_accounts`, `challenge_movements`, `challenge_sessions`, `challenge_transfers`, `challenge_users`, `qac_attempts`, `qac_bug_reports`, `qac_catalog`, `qac_scores`, `qac_test_cases` + tablas `talent_application_*` (5).

**Con RLS habilitado y sin políticas, PostgreSQL deniega todo acceso por defecto.** Los módulos QAC y Test App Challenge pueden estar silenciosamente bloqueados para usuarios normales.

**Acción:** Agregar políticas SELECT para `authenticated` donde corresponda y restricciones de ownership en escritura.

### 🟡 WARN — `auth_user_empresa_role` e `is_active_empresa_member` accesibles por `anon`

Un usuario no autenticado puede sondear si un UUID es miembro activo de una empresa vía la API REST. Fuga de información organizacional.

### 🟡 WARN — INSERT siempre verdadero en `process_history`, `process_variables`, `user_tasks`

Cualquier usuario autenticado puede insertar registros sin restricción de ownership.

### 🟡 WARN — Protección de contraseñas comprometidas desactivada

Supabase Auth no valida contra HaveIBeenPwned. Usuarios pueden registrarse con contraseñas filtradas.

### 🟡 WARN — `log_tool_error` accesible por `anon`

Cualquier visitante no autenticado puede escribir en la tabla de errores. Vector de DoS por llenado de tabla o spam de logs.

## ⚡ Performance — Hallazgo

**Ranking: 7 leaderboards cargados en parallel al mount aunque no se muestran**

`apps/frontend/src/app/ranking/page.tsx:820-846` — Al cargar la página, se disparan 7 llamadas simultáneas a `get_leaderboard` para todos los tipos de examen aunque el tab inicial es "Bughunters" (no usa leaderboards).

**Evidencia en logs Supabase:** 7 llamadas consecutivas a `/rest/v1/rpc/get_leaderboard` en cada visita.

**Fix sugerido:** Lazy-load por tab activo:

```typescript
// Cambiar de: cargar todos en mount
// A: cargar solo cuando el tab sea seleccionado
useEffect(() => {
  const key = activeTab as keyof typeof examData;
  if (!isReportes && !isXp && !examData[key]?.length) {
    loadLeaderboard(key);
  }
}, [activeTab]);
```
